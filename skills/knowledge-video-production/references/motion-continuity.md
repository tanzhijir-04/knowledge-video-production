# 连贯动效：OneTake 方法的科普适配

用于新建或修改分镜、设计段内动作，以及诊断“像PPT、节奏平均、转场生硬”。与[分镜连续性与剪辑](storyboard-continuity.md)、[动效配方](motion-recipes.md)配合，沿用同一镜头卡、边界表和验收记录，不建立另一套台账。

## 1. 先找视觉主线，再列特效

新片或大幅重设计时，围绕核心知识变化提出2–3个简短视觉思路，例如“跟着一个请求走”“逐层进入同一系统”“沿同一基准展开对照”。区分的是解释画面的组织方式，不是给同一套卡片换配色。记录开场钩子、持续对象、尺度含义及适合硬切的位置。已确认方向或用户已授权制作时，由导演选定并记录理由，持续推进；不新增三选一审批，不重开已有批准设计。

只有局部修改时沿用现有主线，不扩成全片概念重做。存在参考片且可访问时，可分析动作/停顿分布、构图、速度与声音；记录实测或人工观察及其来源，不能把上游某案例的数据冒充当前参考片测量。无参考片时直接按知识任务设计。

## 2. 边界设计：让观众看见对象被接住

在现有边界表的“前镜交出/后镜接收”中写明：**承接对象ID、前后状态、运动或尺度关系、落点、切换理由**。有意连续的段落，优先让主体、路径、容器或观察基准在可见状态中延续；固定Logo或背景始终存在不算解释链承接。

可选方式：同对象放大揭示细节；容器展开为内部结构；传递物到达并触发下一状态；局部线条延展为下一张图的共同基准。不要靠整页退出、全新整页进入反复组织机制讲解。保留对象身份不等于始终保留同一个DOM节点，观看证据优先于实现形式。

因果承接只用于证据支持的过程。形状相似、颜色相同不能暗示两个事实是同一对象或互为因果。转论点、换时空、切原始证据和有意揭示允许硬切，写明理由；连续变形如果造成错误理解，应改为清晰切换。

## 3. 段内节奏：行动—落定—阅读

每个解释段在现有镜头卡中标出“什么动、什么保持、何时可读”。短动作引导注意，稳定终态供阅读，复杂证据按真实旁白和阅读需求留时；不要求画面与声音同时归零。不要每句旁白按相同时长入场，也不要靠背景漂移掩盖信息没有推进。

先检查一个解释段的动静变化，再看全片的快慢分布。镜头数量与信息密度仍遵循storyboard-design；长镜头中有多个有效知识节拍也成立。旁白、证据可读性和准确性优先于节奏统计。音效从少量有意义的接触、传递、揭示事件产生，沿用audio-and-timing的人声优先规则，不为每个标签配一声提示音。

## 4. 运镜与确定性

相机有任务才移动：跟随传递物、迎接落点、从整体进入局部。先构图终态与阅读区，再安排路径；检查主体屏幕坐标、附着标签、极值和两侧边界。按动作需要轻微提前或滞后，不把固定0.1秒提前、持续手持晃动或每次撞击抖屏写成通用要求。阅读期间稳定，密集图解通常不加弹跳。

使用现有HyperFrames动作与GSAP曲线，不直接换成上游OM库。随机值固定种子；需要物理模拟时预计算并按时间采样，避免依赖上一帧状态。检查顺序播放与乱序直接seek在同一时点结果一致。

快速位移先在真实FPS下看动态预览，发现跳闪/离散重影再评估速度、路径和渲染器支持的时间采样运动模糊。CSS模糊不能证明实现了快门采样；不得宣称现有流水线已具备上游render.py能力。预览使用保持3:2构图的低成本规格，验收后按本用户母版输出，不照搬1080p30/4K16:9预设。

## 5. 验收：连续性是线索，理解才是目标

沿用evidence中的逐镜、逐边界记录。对有意连续的关键边界查看前镜结束、交接中点、后镜落定帧及实际短预览，确认对象可辨认、路径跟得上、尺度含义不漂移、落定后有阅读时间。三个静态端点不足以证明运动连续。

可按“连续承接 / 静态锚定但内容替换 / 无承接且有意硬切 / 意外断裂”记录观察，明确自动测量、AI观看与用户反馈的来源。意外断裂或误导因果需修正；有理由的硬切不扣成不合格。未看的动态片段标记待动态验证。

若后来实现自动追踪，报告检测范围、未覆盖遮罩/遮挡、对象身份误判、人工标注和豁免边界。元素存续、carry分数、节奏统计都不能证明叙事清楚或有创意。只有文档更新时，不得声称实现检测器、通过动态验收或修复旧片。

## 科普示例（本地原创）

“请求为什么等待”一段：手机发出请求代表物 → 相机沿路径跟随 → 到达需要解释的节点 → 节点保留身份并展开内部机制 → 终态停稳供阅读 → 硬切到真实证据。代表物的移动是流程示意，不能仅凭动画推断故障；若无证据，节点受阻仍标为假设。证据镜头的硬切有助区分示意与真实记录，无需强行变形衔接。
