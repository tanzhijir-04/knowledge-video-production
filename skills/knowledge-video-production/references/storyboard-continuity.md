# 分镜连续性与剪辑：create-storyboard本地适配

来源：[TateZhouSiu/create-storyboard-skill](https://github.com/TateZhouSiu/create-storyboard-skill)，核对版本`4b8662e2fee51b37488c77952bbfa302bfeaf36c`。参考其`skills/create-storyboard/SKILL.md`与`references/storyboard_workflow.md`，改写为本地科普流程。上游版权及MIT许可保留在[许可文件](create-storyboard-LICENSE.txt)。这是方法融合，不是原版完整安装或对其脚本的运行验证。

## 适配边界

本流程使用HyperFrames、Vox视觉语言、稳定scene_id/shot_id及中/高密度设置。镜头是观看单元，composition是工程单元，不强制一镜一文件或一镜一次生成。Seedance的15秒上限、Image 2/剪映专用材料、双语提示词和人物情绪字段不作为全片硬要求；实际使用相应平台/人物情节时再补充。本用户批准稿、规格和视觉契约优先，不把现有决定重新变成问卷。

## 1. 先锁定复用对象与空间规则

在frame.md和现有素材账本中集中记录复用对象的身份、形态、状态、方向、位置基准、尺度含义、配色及参考资产ID。只有人物或真实空间镜头才需要额外检查服饰、视线、轴线和光向，不为纯图解造人物档案。

科普图解尤其固定：同一颜色指代什么、箭头方向代表什么、数据的单位与比较尺度、对象可改变的状态。特写可以改变显示尺度，但不能无说明地改变数量含义。后镜从既有约束继承，不在每次提示或实现中随意重定义。

## 2. 镜头卡必须交代开始、变化与交出

在已有分镜文件中按shot_id保存，不强迫每镜单独建文件。继承storyboard-design已有字段，并补充以下内容；没有使用的可选项写明不适用，而非捏造。

| 项目 | 必须回答 |
|---|---|
| 目的与密度 | 本镜让观众新增理解什么？中/高密度下哪些信息先读、哪些作参照？ |
| 接收状态 | 从上一镜继承哪个对象、视线落点、运动方向或声音？开场镜交代初始定位 |
| 开始→关键动作→结束 | 三个状态分别是什么？主要动作如何解释变化？何时落定供阅读？ |
| 构图与镜头 | 观察尺度、主体位置和主要相机动作是什么？静止也可作为有理由的选择 |
| 交出状态 | 最后可用画面给下一镜留下哪个对象、位置、形状、路径或问题？末镜交代收束 |
| 参考与层次 | 使用哪些真实资产ID？哪些独立运动？什么是遮罩、注释、证据？ |
| 剪辑与替代 | 从哪里切入/切出？风险是什么？失败时如何保留原有知识任务？ |

每镜保持一条清晰主动作链；复杂拆解可以有多个辅助节拍，但不把多个视点变化和多个论点塞进同一个短镜头。镜头长度由可读性和配音决定，沿用本地镜头数量规划，不机械套固定片长。

## 3. 在生成素材前设计相邻镜头边界

在`design/storyboard/`现有分镜中增加一张承接/剪辑边界表即可，不复制成两套不一致的矩阵。每个相邻镜头对一行：

`边界ID | 前镜→后镜 | 前镜交出/后镜接收 | 空间或运动方向 | 视觉承接/遮挡物 | 声音承接 | 切出与切入点 | 剪辑类型及理由 | 是否需精确匹配 | 风险与替代 | 预览/审查状态`

无声音桥接写“无”，不强制新增音效。允许直接切换新主题，但写明重置的是时间、空间还是论点，不能只写“自然转场”。镜头变化仍须保持科普关系准确，不能为匹配形状而制造虚假关联。

按需要选择承接方式：

- **同对象/同位置**：整体图中选中一个部件，下一镜放大该部件，保留可辨识的锚点。
- **动作/方向**：前镜沿路径向右传递，后镜从对应入口接收；不能方向突然反转而没有说明。
- **构图/形状**：保持阅读落点或形状引导下一对象，明确这是视觉类比而非事实同一。
- **证据/解释**：先让真实材料可读，再切到代码图解；保留来源映射，图解不能冒充原始证据。
- **遮挡**：通过局部纸片或前景覆盖切点，前后两侧检查覆盖完整，不能拿遮挡掩盖错误关系。
- **声音**：必要时用J-cut提前引入后镜声音，或L-cut让前镜声音延续；服从真实旁白时序。
- **有意硬切**：转折、信息揭示或新主题直接切换，记录理由，不为了“丝滑”添加无意义运动。

默认追求可剪辑、可理解的连续性，不要求所有边界像素匹配。只有动作本身必须连续时，才约束对象的端点、速度、尺度、轴线或遮挡轮廓。外部生成素材需要时可留剪辑余量，不能把余量加进已锁定总时长。

## 4. 逐镜制作板与干净素材分开

每镜有可查看的制作板，包含开始、关键动作、结束三个状态，必要时增加接收/交出状态。静止阅读镜头状态相同可复用同一图并标注保持时段，不为凑图重复生成。图上可读元数据包括shot_id、scene_id、预计/实际时段、视觉任务、密度、动作、相邻承接和风险；长说明可链接镜头卡，不用把整表压成小字。

图像模型负责干净视觉素材，板式、编号、时间码、标签和准确文字由HTML/CSS/SVG或其他可控工具合成。素材和制作板分别保存、可追溯；若另做图生视频，文字网格制作板不能当作唯一主输入。全片联系表用于全局审查，不能替代逐镜制作板。

## 5. 先设计失败替代，再逐镜/逐边界验收

资产身份漂移时复用已验收参考或更换素材；动作太复杂时拆为整体、细节与结果镜头；空间跳变时补定位视图或明确重置；动效遮字时调整路径/分层，必要时采用有理由的静态切换。替代方案必须保留原知识变化、证据和所选密度，不能一律退化为大标题。

按visual-acceptance-contract和layout-contract-and-qa执行真实审查。在原生图与小图中逐镜检查，再把每个边界的前镜结束与后镜开始并排核对：接收/交出对象一致吗？方向、尺度、配色含义和阅读落点能跟上吗？切换是否产生错误因果或归属？涉及连续运动的边界还须看实际短预览与切点两侧帧。

按shot_id和边界ID在既有evidence记录证据及修正；改某镜后重查该镜、两侧边界及共享对象受影响的镜头。静态分镜审查不能代替动态验证；只有表格齐全、图片存在或脚本退出成功，都不能宣称画面通过。

## 科普适配示例（本地原创）

| 镜头 | 新增理解与三个状态 | 接收/交出与剪辑 |
|---|---|---|
| sh01：现象，中密度 | 手机与发送对象建立 → 消息停在等待态 → 保留等待消息及手机锚点 | 开场定位；交出手机及消息，不用标题复写整段旁白 |
| sh02：机制，高密度 | 继承手机锚点并展开路径 → 请求经过接入/网络/服务节点 → 选中实际解释的受阻节点 | 从同对象切入；各状态是独立的机制示意，不能据“等待”推断真实故障位置 |
| sh03：证据或条件，中密度 | 接收选中节点 → 展示支持本论点的真实证据/条件 → 留足阅读时间 | 用节点特写或直接切证据；来源不足则保留假设/示意说明，不伪造测量结果 |

示例用于核对执行方式，不是每支片固定的三镜模板，也不表示已经渲染或验收通过。
