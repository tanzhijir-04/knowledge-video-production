# 视频布局：每次制作都执行的检查与纠正闭环

适用于知识视频的HTML/CSS/SVG布局，也适用于继续已批准的Remotion旧工程。先让静止画面关系成立，再动画化。纸面拼贴允许有意倾斜和出血，但精确图解、标签归属与阅读顺序要稳定。不要把本规范变成所有镜头使用相同网格的模板。

执行前读取[视觉验收契约 v1](visual-acceptance-contract.md)，以其八项标准、问题等级和证据要求判定是否通过。本文件说明检查与纠正方法；契约是验收依据。

## 通用方法：生成与审查分开，检查后必须纠正

本节是每次视频制作的默认流程，后面的标签/连线/屏幕只是条件性示例。不能只对照几个已知错误打勾，也不能等用户截图后才检查。

### A. 用真实内容做布局压力测试

先用本片最长标题、最多标签、最大主体和最密集状态搭建代表画面，实际加载字体与图片，查看原生画幅和约540px宽小图。在扩展全片前纠正共同布局问题。内容改变后检查实际内容，不把模板曾经通过当作新画面通过。

优先用共享容器、Grid/Flex、共同间距变量、内容宽度约束和对象相对定位建立布局。绝对坐标适合固定画布中的构图，但相关元素应从共同几何派生。不要用一连串彼此独立的像素补丁修复系统性错位。

### B. 每场预览，做两层检查

使用当前工程的真实渲染/seek机制，确认字体和媒体已就绪；不要擅自假设某个CLI或时间线API存在。保存落定帧和实际风险时点的帧，并检查关键运动片段。

**程序测量层**：复用项目浏览器检查能力，检查文字容器的scroll/client尺寸及实际行框、关键元素与画布/裁切祖先的边界、已声明的对齐组和间距，以及疑似碰撞。先声明哪些元素应对齐、哪些重叠是有意的，才有比较依据；不能将任意两个元素都强制对齐。输出测量值与可疑对象，不把矩形相交自动认定为错误，更不自动挪动所有碰撞对象。没有测量工具时明确记为未执行，以实际帧审查继续推进，不伪称自动检测通过。

**画面审查层**：实际打开渲染图，暂时按审稿者而非作者的角度检查。先不读实现说明，判断画面本身是否成立，再回看脚本核对语义。每场回答以下问题，只有发现问题时才详细记录：

| 维度 | 通用判断 |
|---|---|
| 阅读顺序与层级 | 第一眼落在哪里？接下来读什么？装饰或标题是否抢过解释主体？ |
| 构图与重心 | 主体尺度是否合适？视觉重量是否无意挤向一边？留白是否支持关系？不要求左右对称 |
| 疏密与间距 | 局部是否拥挤、另一区域却闲置？组内是否比组间更紧？留白和安全边距是否连贯？ |
| 对齐与节奏 | 同类元素有无理由共用边线、基线或中心？字号、宽度和间距的变化是否有意义？ |
| 文字适配 | 断行是否顺畅？是否存在孤行、过长行、缺字、溢出、贴边或缩小后不可读？ |
| 关系与遮挡 | 按契约的“图形关系专项契约”检查连接、归属、包含、对照、交叉与前后关系；画面是否暗示了错误因果、范围或尺度？有没有无意擦边或切线？ |
| 动态稳定性 | 入口、超调、缩放、交叉和转场中关系是否保持？是否只在某一帧恰好排好？ |

程序测量不能替代画面判断；画面看过也不替代可测的溢出检查。发现一次普遍问题，就把同类场景一起检查，而不是只修用户指出的一帧。

### C. 把问题变成具体修改，再回到同一画面

每个待修项写明场号、时间/帧、对象、可观察问题、原因假设和拟修改。例如“右侧说明与图像太近，缩略图中被读成同一组；扩大组间距并统一说明宽度”，不要只写“优化排版”。按以下顺序纠正：

1. 先修构图与信息分组，再修容器尺寸、对齐与间距，最后修字距和光学偏移。多处同时偏移优先查父级、坐标空间或字体加载。
2. 长文字先语义换行/调整区域；精简需保留原意，改变批准论点不属于排版修正。不要默认缩小所有文字。
3. 问题来自素材透明边、视角或比例时，处理素材或重构图，不持续堆叠补偿坐标。
4. 导出同一时点的修正后帧，与修正前对照；重看动态及相邻转场，检查修改是否引入新的挤压、遮挡或跳变。

普通布局修正由agent在已有授权内持续完成，不把清单交给用户代为检查。连续两轮对同一问题微调仍无改善，就回到分组/容器/构图重新安排，停止堆像素补丁。资源不足或受输入限制时，记录未解决项和实际阻塞，不能将“检查脚本退出成功”写成视觉通过。

### D. 全片覆盖与变更复查

在现有evidence目录保存一份简短的`layout-review.md`或等价JSON，包含场景与检查时点、真实预览路径、已执行的测量/视觉检查、待修项、前后对照和结论。已通过的场景可只留一行索引，不为每帧写长报告。联系表用于发现跨场景的字号漂移、密度失衡和重复构图；发现疑点必须打开原图，不能只看缩略联系表放行。

- 第一道检查：代表画面，避免共同问题扩散。
- 第二道检查：每个场景实现后，纠正实际内容引起的问题。
- 第三道检查：全片预览与最终编码抽查，检查场景之间和渲染后结果。
- 字体/共享组件/全局尺度变更：重查所有使用它的场景；单场局部变更：重查该场及相关转场；时序变更：重新选风险时点。未变化范围可复用有效证据。

通过条件是：全片场景均有检查记录，已发现的阅读/理解缺陷已修正并复查；有意重叠、非对称、倾斜和出血有清晰语义且实际可读。不存在能保证审美的单一分数，检查清单全部填满也不能代替看真实画面。准确标注AI画面审查、程序测量和用户亲自观看，不能互相冒充。

## 1. 每场先确定空间关系

在项目frame.md记录全片设计坐标、画幅、安全边距、字体与间距尺度。在分镜或场景实现旁记录本场的主关系、对象归属、共同边线/中心线、预期裁切和遮挡顺序；沿用现有文档，不另造重复表单。

- 设计坐标与输出像素只转换一次，例如1920×1280设计稿整体映射3840×2560。HTML、SVG viewBox、图层和相机使用同一套坐标；不能各自再乘缩放比例。
- 标题区与解释区有明确边界，但不强制固定高度。正文最长的一帧先排，标题过长先按语义断行或精简，再调整区域比例，最后才考虑缩字号。
- 以画幅短边约4%作为初始安全边距，再按内容调整；这是起点，不是统一裁切合同。关键文字、节点及端口留在安全区；照片/纸张的出血可有意越界并记录。封面裁切另按发布规格检查。
- 对齐使用具体对象：共同左边线、同一文字基线、节点中心或照片可见轮廓。透明PNG的文件框不等于主体框；先检查alpha外接框与透明留白，再定锚点。
- 先检查最终静态图，关闭入口、漂移和装饰效果。静态失败时不靠动效掩盖，也不把有解释作用的图解删成稀疏标题页。

## 2. 文字与标注从所属对象派生

同一排节点共用中心线；节点内文字用flex/grid居中或明确基线。对象、附属标签、状态图标与高亮共用一个局部坐标组。标签相对其所属对象定位，不分别写互不关联的left/top。对象移动、缩放、换字后，附件仍保持关系。

```html
<div class="node" style="--x:680px;--y:720px">
  <div class="node-body">网络</div>
  <div class="node-label">网络连接</div>
</div>
<style>
.node { position:absolute; left:var(--x); top:var(--y);
  width:240px; height:160px; transform:translate(-50%,-50%); }
.node-body { box-sizing:border-box; width:100%; height:100%;
  display:grid; place-items:center; border:3px solid; }
.node-label { position:absolute; top:calc(100% + 28px); left:50%;
  transform:translateX(-50%); white-space:nowrap; }
</style>
```

示例只说明局部坐标与绑定，不规定节点尺寸或全片画风。需要动画时在外层包装组做整体运动，避免GSAP覆盖定位层的translate。超长标签使用有宽度的语义换行，不能无限nowrap。

- 居中标签对准所属节点中心；左对齐标签对准其共同边线。必要的光学微调可保留，但记录理由。不要把独立left值的偶然接近当作对齐。
- 中文段落检查真实行框、标点禁则、单位与数字、孤行和底部空间。text-align:center只处理文字行，不保证容器与主体对齐。
- 标注靠近目标且与其他对象拉开距离；若归属有歧义，用短引线指向目标边缘，或重排。不要在长连线附近随意散放标签。

## 3. 连线有端口、避让和层级

先按[图形关系专项契约](visual-acceptance-contract.md)确定关系类型。连线只是表达手段之一；容器、空间排列、共同基准和物件叠放同样要接受语义检查。先纠正错误的关系与分组，再处理路径美观。

- 从节点几何或共享坐标数据推导端点：源的出端口到目标的入端口，落在可见边缘，不能穿入文字、设备屏幕或人物脸部。表示进入屏幕的内容需有明确入口/遮罩和语义说明。
- 路径先确定端点，再确定弯曲/折点；SVG使用同一设计坐标。不要用手感调出的贝塞尔曲线补救错位端点。
- 普通连接线在节点/照片后层，状态标记和标签在前层；光靠z-index遮住错误路径不算避障。检查可见线段是否穿字、误连其他对象、形成无意切线或擦边。
- 线端与对象可以接触或留一致的小间隙，由语义决定；不能一端贴合、一端悬空。箭头只在有方向意义时使用。
- 曲线上标签使用带不透明纸色底的局部遮罩，或与线留净距，不让线穿过字。多个支路分开端口/通道，使来源与去向可追踪。
- 对象运动时，连线、端口与标签从同一时点的几何派生，或作为同组整体运动；不能仅终态连接正确。

## 4. 照片内的UI属于照片平面

图标若表示手机屏幕内的信号/加载状态，就属于屏幕，而非画布的独立贴纸：确定屏幕可见四角，在同一局部平面内排版，将整体映射到照片透视，并按屏幕轮廓裁切。若画面是正视手机，可用共同缩放/旋转；有透视时只旋转图标不足以贴合。

无法可靠映射时，优先换正视角素材或把图标明确画成屏幕外带引线的解释标注。不要继续叠一个看似屏幕内容、实际与照片错位的正面图标。实物与UI一起运动，检查屏幕边缘、圆角、刘海遮挡及视觉留白。

## 5. 每场留下可核对的布局证据

代表帧通过只允许扩展制作。全片按场景覆盖，复用同一模板也要检查实际文字与对象位置。沿用evidence目录，记录场号、实际时间/帧号、检查类型、发现问题、修正与修正后图片路径，以及对应输入版本。

| 检查时点 | 需要确认 |
|---|---|
| 每场最终可读终态 | 原生分辨率看文字、边缘、端口；约540px宽小图看归属、主次与可读性 |
| 最长文字、最密集状态 | 无溢出/孤行、标签不挤占主体、留白有层次 |
| 入口最大超调、运动交叉、相机极值 | 移动标签/连线不脱离目标；缩放/旋转后无意外越界 |
| 转场中点及切点前后一帧 | 无穿字、残影、意外空场、裁切跳变 |

按实际事件选风险时点，不用固定25%/50%/75%抽帧替代；关键动作要看连续片段，离散截图不能证明运动全程正确。最终MP4抽查必须来自最终编码；改变布局、字体、素材或时序后，重验受影响场及相邻转场，旧图不能冒充修正证据。

可用实际浏览器字体加载完成后的DOM边界/Range行框检查文字溢出，测量共享边线、中心与端口距离；需要自动检查时优先复用当前工程工具，不虚构CLI参数。测量时先统一坐标空间，区分有意重叠/出血和意外碰撞。CSS检查或包围框相交只能辅助，不能判断可见alpha轮廓、中文光学对齐、贝塞尔曲线穿字及照片透视。

## 不予视觉通过的具体问题

错标归属、意外文字遮挡/裁切、断裂或误连的连接线、屏幕内容脱离实物平面、运动导致的附件漂移，均需局部修正并复验。技术解码通过、分辨率正确、三张好看的代表帧、纸面风格的“随意感”都不能豁免这些问题。时间不足时保留“待视觉验收”状态，不宣称成片已通过。

规范更新只证明制作要求已改；没有重新渲染、查看原有视频，就不能声称旧片问题已经修复。
